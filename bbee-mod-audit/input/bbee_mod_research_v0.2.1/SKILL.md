# 使用前读取

先阅读 `角色制作清单.md` 确认任务状态与下一步，再读 `研究笔记.md`；按需要查阅 `zenith_source_evidence.md` 与 `static_audit.json`。这是固定上传包的项目知识，不是所有《苍翼》版本和所有 Mod 框架的通用 API 文档。

## 核心约束

1. 不将本路线误写成 BepInEx DLL 注入。当前包以 Python 构建、JS/配置修改、AssetBundle 和 merge/manifest 更新为主。
2. 先确认游戏 build 与原始基线。描述符 gameBuilds 不是你已经验证运行成功的证明。
3. terminal.json 负责 GUI prepare；mod.json 才是组合器描述。Ruby 初次无 mod.json 是正常预生成状态。
4. 按 setup → prepare → tables/JS/locale → clone/import → assets → encode/install 的依赖顺序推导。
5. 分开角色 ID、动作名、动画名、PPtr、managed reference RID、manifest/GUID。保留大整数精度，只解码确认类型的固定点字段。
6. SkillActivate 键为 ActorId/Group/Order。当前 SkillDamage 键不包含 Action，而且 $append 与普通索引不同；未审阅前不要生成按动作改伤害的普通覆盖补丁。
7. 新增角色先完成选择、移动、受击、死亡、一次命中、退出重开闭环，再扩展内容。
8. 保留独立存档备份。安装和关闭自定义角色可能触发清理；不要把删文件夹当成卸载。
9. 修改 Ruby src/own/素材后明确重新生成，不假设顶层 mtime 检查一定识别它们。
10. 明确区分：源代码可证、静态检查通过、离线组合通过、真实游戏通过。不得把语法检查当成功运行或安全证明。
11. 不宣称源码包含所有作者工具。对缺失模块和真实游戏接口先取证，不编造类名/路径。
12. 不再分发原包字体、商业游戏素材或原始二进制；原创素材也需匹配实际帧/网格数据结构。

## 当前已验证最小样例

`study-kris-input-buffer` 依赖 dr-party，把 (200801,1,1).Preinputtime 从 0.20 改为 0.30。四项离线组合测试已通过，游戏内未测试。

## 扩展研究所需证据

优先获取本地 build 标记、指定模块/表、Ruby prepare 后的描述符/动作树与日志。不要索取账号凭据、整个商业游戏包或完整个人存档。

## 新角色项目执行（v0.2.1 文档补充）

- 目标是人物 Mod；具体人物、核心机制、素材路线与首版范围尚未确定，不将举例或建议当成用户已确认需求。
- 用户定角色/玩法方向并提供本地测试结果；开发侧承担规格拆解、独立工程、资源适配、逻辑实现与修复，不把技术缺口全部转给用户。
- 先验证现成角色与受控修改，再完成独立角色的最小运行闭环；完整成长、语音、多形态与复杂演出随后扩展。
- BBTAG 素材导入器不是通用 PNG 导入器；原创素材需验证转换流程。占位素材通过不代表正式动画、判定与手感通过。
- 首版验收与所需输入以 `角色制作清单.md` 为入口。本版仅更新文档，不宣称完整新角色、安装、卸载或游戏兼容已通过。
